# 迭代编码规则

本文档用于指导后续基于当前 RuoYi-Vue3 分离版项目进行业务迭代、代码生成、手写扩展、联调验证和部署配置修改。

当前项目根目录：

```text
/home/lemon/test-project
```

## 1. 基本原则

1. 先确认需求边界，再改代码。每次迭代至少明确：业务对象、页面入口、权限点、数据表、接口范围、是否需要导入导出、是否涉及字典或定时任务。
2. 优先沿用 RuoYi 原有模式，不另起一套框架。后端沿用 `Controller -> Service -> Mapper -> XML -> MySQL`，前端沿用 `api -> views -> permission/menu`。
3. 小步提交、小步验证。每个业务模块完成后至少验证后端构建、前端构建、登录、菜单、列表查询和主要增删改查。
4. 业务代码不要写进基础框架层。`ruoyi-common`、`ruoyi-framework` 只放通用能力；普通业务模块不要改动这些目录，除非确实是在扩展全局能力。
5. 配置变更必须同步文档。端口、数据库账号、Redis、上传目录、日志目录、代理地址、Nginx 路径等变更，都要同步更新 `README.md` 或 `docs/环境变量说明.md`。

## 2. 项目结构认知

当前工作区不是单一 Git 仓库，而是外层项目目录加两个上游源码仓库：

```text
test-project/
├── backend/              # 后端 RuoYi-Vue，独立 Git 仓库
├── frontend/             # 前端 RuoYi-Vue3，独立 Git 仓库
├── infra/                # MySQL、Redis、Nginx、本地字符集配置
├── scripts/              # 本地构建、启动、停止、状态检查脚本
├── docs/                 # 项目文档和验证记录
├── logs/                 # 本地运行日志，不提交
├── uploads/              # 本地上传文件，不提交
└── .tools/               # 项目内置 JDK/Maven，不提交
```

后端核心目录：

```text
backend/ruoyi-admin/      # 启动入口、Controller、配置文件
backend/ruoyi-system/     # 系统与多数业务 Service、Mapper、Domain
backend/ruoyi-common/     # 通用工具、AjaxResult、BaseController、注解、异常
backend/ruoyi-framework/  # 安全、Redis、MyBatis、Druid、Token、全局异常等框架能力
backend/ruoyi-generator/  # 代码生成器
backend/sql/              # 初始化 SQL
```

前端核心目录：

```text
frontend/src/api/         # 接口封装
frontend/src/views/       # 页面
frontend/src/components/  # 通用组件
frontend/src/router/      # 固定路由
frontend/src/store/       # Pinia 状态
frontend/src/utils/       # request、权限、字典、时间、下载等工具
```

## 3. 后端迭代规则

新增普通业务模块时，优先遵循 RuoYi 代码生成器产物结构：

```text
backend/ruoyi-admin/src/main/java/com/ruoyi/web/controller/{module}/XxxController.java
backend/ruoyi-system/src/main/java/com/ruoyi/system/domain/Xxx.java
backend/ruoyi-system/src/main/java/com/ruoyi/system/mapper/XxxMapper.java
backend/ruoyi-system/src/main/java/com/ruoyi/system/service/IXxxService.java
backend/ruoyi-system/src/main/java/com/ruoyi/system/service/impl/XxxServiceImpl.java
backend/ruoyi-system/src/main/resources/mapper/{module}/XxxMapper.xml
```

当业务域明显变大，且不适合继续放在 `ruoyi-system` 时，再考虑新增独立 Maven 模块，例如 `ruoyi-business`。新增模块时必须同步：

```text
backend/pom.xml
backend/ruoyi-admin/pom.xml
application.yml 中 MyBatis 扫描规则，如有必要
```

后端接口必须遵循：

- Controller 继承 `BaseController`。
- 列表接口使用 `startPage()` 和 `getDataTable(list)`。
- 普通返回使用 `AjaxResult.success()`、`success()`、`error()`、`toAjax()`。
- 增删改接口使用 `@Log` 记录操作日志。
- 需要登录权限的接口使用 `@PreAuthorize("@ss.hasPermi('模块:业务:动作')")`。
- 新增和修改入参使用 `@Validated @RequestBody`，领域对象字段用校验注解约束。
- 不在 Controller 写复杂业务逻辑；Controller 只做鉴权、参数接收、简单编排和返回。
- SQL 写在 Mapper XML 中，避免在 Service 中拼接 SQL。

权限命名统一使用：

```text
{module}:{business}:list
{module}:{business}:query
{module}:{business}:add
{module}:{business}:edit
{module}:{business}:remove
{module}:{business}:export
```

注意：实际权限字符串不要包含花括号，示例应写成：

```text
system:user:list
system:user:query
system:user:add
system:user:edit
system:user:remove
system:user:export
```

数据权限相关模块要优先复用 RuoYi 已有能力：

- 当前用户：`SecurityUtils.getUserId()`、`SecurityUtils.getUsername()`。
- 数据权限：参考 `SysUserController`、`SysRoleController`、`@DataScope`。
- 密码加密：`SecurityUtils.encryptPassword()`。
- 字典：优先使用系统字典表和前端 `useDict()`。
- 导入导出：优先使用 `ExcelUtil` 和 `@Excel`。

## 4. 前端迭代规则

新增页面时，接口和页面必须成对出现：

```text
frontend/src/api/{module}/{business}.js
frontend/src/views/{module}/{business}/index.vue
```

前端接口封装必须使用：

```js
import request from '@/utils/request'
```

列表、详情、新增、修改、删除接口命名优先使用：

```text
listXxx
getXxx
addXxx
updateXxx
delXxx
```

页面开发规则：

- 使用 Vue 3 `<script setup>` 写法，贴合当前项目风格。
- 表格、表单、弹窗、分页优先参考 `frontend/src/views/system/user/index.vue`。
- 权限按钮必须使用 `v-hasPermi`，权限字符串要和后端、菜单按钮权限一致。
- 请求错误处理交给 `frontend/src/utils/request.js`，页面内不要重复写通用错误弹窗。
- 日期范围查询优先使用 `proxy.addDateRange()`。
- 导出优先使用 `proxy.download()`。
- 字典展示优先使用 `useDict()` 和 `DictTag`。
- 动态菜单页面必须和数据库菜单 `component` 路径一致，例如 `system/user/index`。

新增菜单时必须同时确认：

- 菜单路径 `path`
- 组件路径 `component`
- 权限标识 `perms`
- 菜单类型：目录、菜单、按钮
- 是否缓存页面
- 是否隐藏菜单
- 前端真实文件路径存在

如果浏览器端看不到新菜单，优先检查：

1. 当前用户是否拥有菜单权限。
2. 后端 `/getRouters` 是否返回该菜单。
3. 菜单 `component` 是否能匹配 `frontend/src/views/**/*.vue`。
4. 前端是否需要退出登录后重新登录，以重新拉取动态路由。

## 5. 数据库与 SQL 规则

本地 MySQL 由 Docker Compose 提供：

```text
infra/docker-compose.yml
```

数据库初始化 SQL 位于：

```text
backend/sql/quartz.sql
backend/sql/ry_20260417.sql
```

数据库规则：

- 所有中文 SQL 文件必须使用 UTF-8 保存。
- 导入 SQL 时必须使用 `utf8mb4`，避免再次出现中文乱码。
- 表名建议使用小写下划线，例如 `biz_customer_order`。
- 主键优先使用自增 `bigint`，字段命名使用小写下划线。
- 业务表建议包含 RuoYi 常用审计字段：`create_by`、`create_time`、`update_by`、`update_time`、`remark`。
- 逻辑删除、状态字段、类型字段要明确字典值，不要把魔法字符串散落在前后端。
- 修改已有初始化 SQL 前，先备份数据库。

当前字符集防护配置在：

```text
infra/mysql/conf.d/charset.cnf
```

如果需要重置数据库，必须先确认本地数据可以丢弃，再执行删除 Docker volume 或重新导入 SQL 的操作。

## 7. 每次迭代的推荐流程

1. 阅读相关现有模块，优先找 RuoYi 已有相似实现。
2. 设计数据表和权限点。
3. 用代码生成器生成基础 CRUD，或按生成器结构手写。
4. 调整后端 Controller、Service、Mapper XML。
5. 调整前端 API、页面、字典、权限按钮。
6. 在菜单管理中配置菜单和按钮权限。
7. 给角色分配权限。
8. 构建后端和前端。
9. 启动服务并进行接口验证。
10. 浏览器端验证登录、菜单、列表、新增、修改、删除、导出等主流程。
11. 更新对应文档和验证记录。

```bash

./scripts/start-backend.sh
```

前端最低验证：

```bash
./scripts/build-frontend.sh
./scripts/start-frontend.sh
```

基础功能验证：

- `GET /captchaImage`
- `POST /login`
- `GET /getInfo`
- `GET /getRouters`
- 新模块列表接口
- 新模块新增接口
- 新模块修改接口
- 新模块删除接口

浏览器验证：

- 登录是否正常。
- 菜单是否显示。
- 按钮权限是否生效。
- 查询条件是否生效。
- 分页是否生效。
- 表单校验是否生效。
- 新增、修改、删除后列表是否刷新。
- 涉及中文数据时确认没有乱码。

## 9. 安全与上线前规则

上线前必须修改或确认：

- `token.secret`
- 数据库 root 密码
- 数据库业务用户密码
- Redis 密码
- Druid 管理页面账号密码或关闭 Druid
- 默认管理员密码
- Nginx `/prod-api/` 代理
- 上传目录权限
- 日志目录权限
- 防火墙开放端口
- 是否暴露 Swagger、Druid、数据库、Redis

禁止把以下内容提交到仓库：

```text
.tools/
logs/
uploads/
frontend/node_modules/
frontend/dist/
backend/**/target/
```

## 10. 不要做的事

- 不要直接在 Windows 本地目录 `/mnt/d/python-vscode` 中作为本项目主开发目录。
- 不要绕过 `frontend/src/utils/request.js` 直接使用裸 `axios`。
- 不要在前端硬编码后端完整地址，开发环境走 `/dev-api`，生产环境走 `/prod-api`。
- 不要在 Controller 中写大段业务逻辑。
- 不要在 Service 中拼接未转义 SQL。
- 不要随意删除 Docker volume 或重新导入 SQL，除非已确认数据可丢弃并完成备份。
- 不要把业务代码塞进 `ruoyi-common` 或 `ruoyi-framework`。
- 不要修改 RuoYi 基础能力后不做登录、权限、菜单回归验证。
- 不要新增菜单后忘记配置角色权限。
- 不要只验证接口不验证浏览器动态路由。
